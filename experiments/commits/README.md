# Experiment commits

30 small, developer-style changes used by the paired replay experiment (PLAN.md §4 Phase 6).
`scripts/replay.py` reads `manifest.toml`, applies each patch **on its own** to the base ref
(`git apply`), commits it on an `exp/<label>/<id>-<category>` branch and pushes it, so every pipeline
variant runs on identical inputs. The patches are never stacked.

## Categories (5 patches each, ids interleaved 1 frontend, 2 backend, 3 analytics, 4 shared-lib, 5 docs, 6 config, 7 frontend, ...)

| Category | What a patch may touch | What TIA should see |
|---|---|---|
| `frontend` | `apps/web/src/**` only (lib, components, pages, tests) | web sources/tests only |
| `backend` | `apps/orders-api/src/main/java/**`, `src/test/java/**` | orders-api sources/tests only |
| `analytics` | `apps/analytics/app/**` (not `app/generated/**`), `apps/analytics/tests/**` | analytics sources/tests only |
| `shared-lib` | `libs/shared-schemas/schemas/*.json` plus the files regenerated by `codegen.py` (Java records, `apps/web/src/generated/schemas.ts`, `apps/analytics/app/generated/schemas.py`) and the small app changes needed to keep all three apps compiling | all three apps |
| `docs` | Markdown only | nothing to run |
| `config` | app-level config: `application.yml`, `nginx.conf`, `eslint.config.js`, `pyproject.toml` (ruff), `.dockerignore` | the configured app's full suites |

No patch touches `.github/**`, `tia.toml`, `tools/**`, `scripts/**`, `experiments/**`, `PLAN.md`,
`CLAUDE.md`, `codegen.py`, any `Dockerfile*`, `playwright.config.ts`, `vite.config.ts`, lockfiles or
dependency versions. The verification script checks every patch's paths against these rules.

The changes are real: features with tests (percent-change formatter, quarterly granularity, funnel
conversion, `PageResponse.hasPrevious`), edge-case fixes (whitespace in ids, coupon-code normalisation,
stricter e-mail parsing, negative-amount guard), refactors and renames, schema additions, docs and
config tweaks. They touch 1 to 7 files each.

## How they were made

Each patch was written in a separate git worktree on `phase0-weight`, captured with
`git add -A -N && git diff` (unified diff, repo-relative paths, LF line endings), and the worktree was
reset before the next one. Shared-lib patches were produced by editing the schema and running
`python libs/shared-schemas/codegen.py`; generated files were never edited by hand.

## How they were verified

Every patch was verified on its own: clean worktree at `phase0-weight` (commit `80685a6`),
`git apply --check`, `git apply`, then the suites of every app it touches, then
`git checkout -- . && git clean -fd`. The `verified` field in `manifest.toml` lists the steps that
passed for that patch.

| Suite | Commands |
|---|---|
| orders-api | `./mvnw -B -q verify` (JDK 21, all unit tests + Testcontainers ITs) |
| web | `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `CI=1 npm run e2e -- --project=chromium --project=webkit` |
| analytics | `ruff check .`, `pytest -q` |
| shared-lib | `python libs/shared-schemas/codegen.py --check` plus all three app suites |
| docs | `git apply --check` only |

`CI=1` was set for e2e so Playwright never reuses a preview server already running on port 4173.

## Caveats

- **Firefox e2e was not run locally.** The Playwright Firefox build (firefox-1555) does not start on
  this Windows machine ("side-by-side configuration is incorrect"), so local e2e covered the
  `chromium` and `webkit` projects only. The pipelines still run all three browser projects.
- Patch 12 (`nginx.conf`) is not exercised by any test suite. It was additionally checked with
  `nginx -t` and a gzip smoke request inside the existing `web:local` image. Patch 30
  (`.dockerignore`) was not checked with a `docker build` (that would have pulled base images); both
  Dockerfiles and Dockerfile.ci were read to confirm the excluded paths are not copied or used.
- Shared-lib patches 16 and 22 touch 7 files (4 and 10 and 28 touch 6): a new record component
  changes the Java canonical constructor, so every `new X(...)` call in orders-api mappers and tests
  changes too, on top of the schema and three regenerated files.
- The suites were run on `phase0-weight` at `80685a6`. All 30 patches also pass
  `git apply --check` against `main` at `b17eecf` (the only differences in the touched areas are ADRs
  the patches do not edit), but the suites were not re-run on `main`. If the base moves, re-run
  `git apply --check` for each patch before a replay round.
- Total verification time was 55 minutes (sum of per-patch times, sequential, on the author's
  Windows laptop).
