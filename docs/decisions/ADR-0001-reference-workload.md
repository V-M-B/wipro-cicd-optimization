# ADR-0001: Reference workload is a polyglot monorepo ("RetailOps")

**Status:** accepted

## Context
The dissertation needs a pipeline that resembles a typical enterprise engagement and that is slow enough
for optimizations to be measurable. Client code cannot be published.

## Decision
Build a synthetic but realistic monorepo with three services in three ecosystems (Java/Maven,
TypeScript/npm, Python/pip) and one shared schema library whose generated code is consumed by all three.
Test suites are large, split across many files/classes, and include slow integration (Testcontainers),
e2e (Playwright) and data-heavy tests. Some repetitive test tables are generated by scripts; every generated
test asserts real behavior. Each app README records how many tests were generated.

## Consequences
- Three caching strategies and three test frameworks must be handled, which matches real Wipro estates.
- The shared library creates genuine cross-service impact for test impact analysis.
- Threat to validity: the workload is synthetic. Reported in the dissertation's validity section.
