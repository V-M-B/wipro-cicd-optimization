# Phase 4 results, part 1 — test impact analysis safety (fault injection)

**Status:** safety study complete. The CI-time part (tests executed and minutes saved on the 30 replay commits)
is measured in replay round A and reported separately.

## Method

- `scripts/inject_faults.py --per-app 20 --seed 7` generated 60 single-site mutations in production code
  (relational/logical/boolean flips, off-by-one, constant change, negation removal), 20 per app. String literals,
  comments and Python docstrings are masked so every mutation changes executable code.
- `scripts/eval_tia_faults.py` applies each fault in an isolated worktree, computes the `tia` selection for the
  changed file in two modes, runs the app's **full** suite once, and records the failing test units.
  - **hybrid:** static import graph, the nightly coverage map (from nightly-full run 40211259654), and the safety rules.
  - **static-only:** the import graph and safety rules, with no coverage map.

  A fault counts as detected by the selection if any failing unit is in the selected set. That is the same outcome
  as running the subset, without a second run.
- Faults that no test detects are excluded from recall, because no selection can do better than the full suite.
  They are listed in the tables file as gaps in the test suites.
- Web e2e is not part of the comparison: `tia` always runs the whole e2e suite on any web source change.

## The miss that changed the design

The study did not pass first time. That history is kept as evidence:

1. `experiments/results/tia-faults-20261025T173830Z.json` is the first full run. Its analytics faults turned out to
   include docstring-only "mutations", which are not faults. The generator was fixed to mask docstrings, and the
   analytics faults were regenerated. The orders-api and web faults are byte-identical across all runs.
2. `experiments/results/tia-faults-20261025T174819Z.json` is the regenerated analytics run. Hybrid recall was 93.3%:
   **one miss**, `analytics-19`, a changed default in `app/api_models.py`. Two blind spots caused it at the same
   time:
   - The coverage map attributes import-time code (defaults, constants) to no test.
   - The hub rule that was then in place cut the only static path, through the `client` fixture in `conftest.py`.
3. Fix (ADR-0005 addendum 2): hubs are resolved per requested pytest fixture. The final run selects 8 analytics
   test files for that fault, including `tests/api/test_products_api.py`, which detects it.

Selection cost of the fix: the analytics mean share rose from 25.3% (unsafe rule) to 43.2% (safe rule).

## Findings

- **Coverage alone is not safe.** Import-time code is invisible to per-test coverage. Static analysis must cover it.
- **Static alone is safe here, but coarse:** it selects 1.3–2.5× more test units than hybrid. On the web app the gap
  is largest, at 77.6% vs 31.2%, because widening to mirrored folders is broad when there is no map.
- **Integration tests set a floor for Java.** All 7 IT classes run on any source change (ADR-0005), so orders-api
  selection cannot go below 7 of 40 units.
- **Test-suite gaps:** 13 of 60 mutations survive the *full* suites, for example the e-mail validator's final
  `return false` and two retry/boundary checks in the web API client. This is a mutation-testing result about the
  suites, not about TIA.

## Threats to validity

The mutations are synthetic and single-site. The 60 sites are drawn from 90 production files. A single nightly map
was used, so map staleness was not studied beyond the 7-day rule. Selection was evaluated per changed file; the
replay commits (round A) cover multi-file changes.
