# web — RetailOps back office

React 18 + TypeScript (strict) + Vite single-page app for the RetailOps order-management back office.
It is one of the three workloads of the CI/CD optimisation project (see `../../PLAN.md`). Its test suite is
deliberately large and split across many files so it can later be profiled, sharded and subjected to
test impact analysis.

Pages: dashboard with KPI cards, order list (filter by status/region/text, sort, paginate, CSV export,
state kept in the URL), order detail with status transitions, create-order form with a live price quote,
product catalog with search highlighting, and customer list.

Domain types (`Order`, `OrderLine`, `Customer`, `Product`, `PriceQuote`, enums) come from
`src/generated/schemas.ts`, generated by `libs/shared-schemas/codegen.py`. Do not edit that file.

## Requirements

- Node `^20.19.0 || >=22.12.0` (CI uses Node 20 LTS; also verified locally under the `node:20` image, v20.20.2)
- npm (lockfile committed; always install with `npm ci`)
- For e2e: Chromium for Playwright (`npx playwright install chromium`)

## Business rules (pricing)

Implemented in `src/lib/cart.ts`; every intermediate amount is rounded to cents with banker's rounding
(round half to even, `src/lib/money.ts`).

1. Subtotal = sum of `quantity x unitPrice` per line.
2. Bulk discount per line: quantity >= 10 → 3%, >= 50 → 7%, >= 100 → 10% (each line rounded separately).
3. Tier discount on the amount after bulk: STANDARD 0%, SILVER 5%, GOLD 10%, PLATINUM 15%.
4. Coupon on the amount after tier discount (minimum spend checked against that amount):
   `SAVE10` 10% (min $50), `WELCOME15` 15% capped at $25, `FLAT5` $5 (min $25), `BIG50` $50 (min $300),
   `FREESHIP` free shipping. Codes are case-insensitive and trimmed.
5. Tax on the discounted amount: NORTH 8%, SOUTH 6%, EAST 7.25%, WEST 8.75%.
6. Shipping: NORTH $7.99, SOUTH $6.99, EAST $5.99, WEST $8.99; free when the discounted amount is >= $100,
   with `FREESHIP`, or for an empty cart.

Order status lifecycle: CREATED → PAID → SHIPPED → DELIVERED; CREATED or PAID → CANCELLED.
DELIVERED and CANCELLED are terminal.

The API client (`src/lib/api.ts`) talks to `/api/orders`, `/api/orders/:id` (GET, PATCH `{status}`),
`/api/products`, `/api/customers`, `/api/customers/:id` and `POST /api/quotes`. GET requests are retried
(default 2 retries, exponential backoff from 250 ms, `Retry-After` honoured) on network errors, 429, 502, 503
and 504; POST/PATCH are never retried. HTTP errors are mapped to typed `ApiError` kinds.

## Tests

Counts below are taken from the JUnit XML files written by the runs recorded in "Local timings".

| Suite | Files | Tests | Notes |
|---|---:|---:|---|
| Vitest — `src/lib/**` hand-written | 24 | 543 | pure functions, mostly `it.each` tables (each row is one test case) |
| Vitest — `src/lib/__generated__/**` | 2 | 65 | generated, see below |
| Vitest — `src/hooks/**` | 1 | 6 | `renderHook` |
| Vitest — `src/components/**` | 10 | 55 | Testing Library + user-event |
| Vitest — `src/pages/**` + `App.test.tsx` | 7 | 59 | full pages rendered with the API client mocked (`createMockApi`) |
| **Vitest total** (`reports/junit.xml`) | **44** | **728** | 0 failures, 0 skipped |
| **Playwright** (`reports/e2e-junit.xml`) | **6** | **35** | Chromium; backend mocked with `page.route` |

The mix is intentionally uneven. In one plain `npm test` run the JUnit per-file times were: lib files
6–125 ms, component files 0.15–1.4 s, page files 1.6–4.1 s (the slowest is usually
`src/pages/CreateOrderPage.test.tsx`); e2e tests took 0.6–5 s each. Per-file times vary from run to run.

Determinism: no test touches the network. Component tests inject a mock `RetailApi` through `ApiProvider`;
API-client tests inject a fake `fetch` and a no-op `sleep`, so retries never wait. Tests that depend on
"now" fix it with `vi.useFakeTimers({ toFake: ['Date'] })` + `vi.setSystemTime(FIXED_NOW)` (Vitest) and
`page.clock.setFixedTime(FIXED_NOW)` (Playwright). The e2e mock backend is recreated per test, so specs run
fully parallel. There are no artificial sleeps; the only real waits are the API client's genuine retry
backoff (250 ms + 500 ms) in two resilience e2e tests. All 35 e2e tests passed in 3 consecutive repeats
(`--repeat-each=3`) and with 2 workers.

Coverage (`npm run test:coverage`, V8, `src/**` excluding tests, fixtures, generated types and `main.tsx`):
statements 98.77%, branches 96.1%, functions 98.13%, lines 99.54%.

### Generated tests

`scripts/generate-tables.mjs` writes **65** of the 728 Vitest tests (2 files):

| File | Tests | Generated from |
|---|---:|---|
| `src/lib/__generated__/quote.generated.test.ts` | 40 | Fixed-seed LCG baskets (1–4 lines, half small / half large, every tier x region, coupons incl. unknown and lower-case codes). Expected `subtotal/discount/tax/shipping/total` come from an **independent integer-cents oracle** in the script (basis-point rates, exact BigInt round-half-even) that transcribes the pricing rules above — not from `src/lib/cart.ts`. The tests therefore cross-check the app's floating-point implementation against a second implementation of the same spec. |
| `src/lib/__generated__/transitions.generated.test.ts` | 25 | Full 5x5 status matrix; allowed edges are written out in the script from the lifecycle spec. Each row asserts `canTransition` and that `transitionOrder` succeeds or throws `InvalidTransitionError`. |

The other 663 Vitest tests and all 35 Playwright tests are hand-written. The generator is deterministic:
`node scripts/generate-tables.mjs --check` exits non-zero if the committed files differ from its output.

## Docker

```
docker build -t web:local apps/web        # from the repo root
docker run --rm -p 8080:80 web:local
```

Multi-stage: `node:20` runs `npm ci && npm run build`, then `nginx:1.27-alpine` serves `dist/` with an
SPA fallback (`nginx.conf`; `/assets/` cached immutably, `/api/` proxied to `orders-api:8080` when run
under docker compose). The Dockerfile intentionally copies the whole app before `npm ci`, so any source
change invalidates the dependency layer; this is the baseline that a later phase optimises.
`.dockerignore` excludes `node_modules`, `dist`, `reports`, `test-results`, `playwright-report`, `coverage`.
